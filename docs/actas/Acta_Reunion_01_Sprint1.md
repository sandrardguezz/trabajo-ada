## 1. Organización inicial del grupo
En esta primera reunión hemos hablado de cómo vamos a organizarnos para empezar a trabajar en el proyecto de Turbine. Hemos puesto en común las primeras tareas que tenemos que realizar y hemos decidido cómo vamos a repartirnos el trabajo durante este primer sprint.


## 2. Reparto de roles
También hemos decidido los roles principales dentro del equipo. 

Se ha establecido el rol de Scrum Master, que se encargará principalmente de ayudar a organizar el trabajo del grupo, hacer el seguimiento del sprint y comprobar que las tareas estén bien organizadas. 

Además, hemos elegido a un Product Owner, que será la persona encargada de tener más presente la visión del producto, organizar las prioridades y ayudar a decidir qué tareas son más importantes en cada momento.


## 3. Organización del proyecto en GitHub
Hemos creado el repositorio de GitHub que vamos a utilizar durante el desarrollo del proyecto. 

También hemos creado un GitHub Project con un tablero para poder organizar mejor las tareas y ver fácilmente cuáles están pendientes, cuáles están en proceso y cuáles se han terminado. 

La idea es utilizar este tablero durante todo el proyecto para poder saber en qué está trabajando cada persona y cómo va avanzando el sprint.

## 4. Identificación de las tareas del Sprint 1

Hemos revisado las tareas que tenemos que realizar en esta primera parte del proyecto y las hemos separado para poder repartirlas mejor. 

Las primeras tareas que hemos identificado son:  
  -Acta de la reunión 1.      
  -Acta de la reunión 2.    
  -Requisitos funcionales y no funcionales.   
  -Identificación de los casos de uso.   
  -Descripción de los casos de uso.   
  -Realización del diagrama de casos de uso.   

Estas tareas se han añadido al tablero de GitHub para poder realizar su seguimiento.

## 5. Reparto de tareas
Una vez definidas las tareas, hemos hablado entre todos sobre cómo repartirlas. 

Se ha hecho una primera distribución y todos los miembros del grupo hemos estado de acuerdo con el reparto. 

Cada tarea tendrá asignada una persona responsable, aunque si durante el sprint alguien necesita ayuda, podremos colaborar entre nosotros.

## 6. Forma de trabajo
Hemos acordado que cada persona irá actualizando en GitHub el estado de sus tareas según vaya trabajando en ellas. 

De esta manera podremos ver si una tarea está pendiente, si ya se ha empezado o si está terminada. 

También hemos acordado comentar cualquier duda o problema que pueda impedir avanzar para intentar solucionarlo entre todos.

## 7. Orden de algunas tareas
Hemos visto que algunas tareas dependen de otras. 

Primero tendremos que tener claros los requisitos funcionales y no funcionales. A partir de ellos pordemos definir mejor los casos de uso y, después, realizar sus descripciones y el diagrama correspondiente. 

Por tanto, aunque las tareas estén repartidas, tendremos que coordinarnos para que todas las partes sean coherentes entre sí.

## 8. Objetivo del Sprint 1
El objetivo principal de este primer sprint es dejar organizada la base del proyecto y comenzar el análisis del sistema Turbine.

Al finalizar el sprint queremos tener definidos los primeros requisitos y casos de uso y avanzar en la documentación necesaria para poder continuar con las siguientes fases del proyecto.

## 9. Seguimiento del sprint
Durante el Sprint 1 iremos revisando el tablero de GitHub para comprobar el estado de las tareas. 

Como Scrum Master, haré un seguimiento general de la organización del sprint y de los posibles bloqueos que vayan apareciendo. 

El Product Owner también podrá revisar las prioridades y ayudar a decidir qué tareas necesitan más atención en cada momento.

## 10. Próximos pasos
A partir de esta reunión, cada miembro comenzará a trabajar en las tareas que tenga asignadas. 

En la siguiente reunión pondremos en común lo que se haya avanzado, las dudas que hayan aparecido y cualquier cambio que sea necesario realizar en la organización del sprint.

## Conclusión
Esta primera reunión ha servido principalmente para organizar el equipo y preparar el comienzo del Sprint 1. 

Se han establecido los roles de Scrum Master y Product Owner, se ha creado y organizado el proyecto en GitHub, se han definido las primeras tareas y se ha realizado una primera distribución del trabajo entre los miembros del grupo. 

Con esto damos por iniciado el Sprint 1.
